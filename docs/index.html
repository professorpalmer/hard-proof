Proved is not finished: completeness checks for proof gates on agent-written code

Cary Palmer · November 2026 · Lean 4.36.0

Paper (PDF) Read the study online Code and data Print page

Abstract

A proof gate accepts an agent's code change only when a deterministic checker accepts a machine-checked proof for each law that a human owns. The gate forces "the code obeys the laws". It does not force "the laws say enough". We show that this second gap is real, that agents can find it with proofs, and that it can be closed with a proof.

An adversary agent supplies a gap certificate: two designs, a proof that each passes each law, and a proved input on which they differ. The same checker that accepts a solution accepts it. The gap becomes one concrete question for the human, the answer becomes a new law, and the loop stops when the checker accepts a completeness theorem.

The study then tests its own claim. A review with no proof duty found most gaps for the same cost. It missed one gap in each of twelve reviews, and the proof adversary found that gap. A review loop stopped early on that fault, and a proof loop ended on a theorem. On 95 real bugs of two shipped products, a pointed agent review found 44 and a full proof pipeline found 31, with 6 that no review found. The other findings of those reviews went up a ladder of evidence, and 51 fixes shipped. One rule of those fixes has a completeness proof.

Reproduce

Clone the repository, install Lean 4.36.0, and run python3 verify_all.py. It runs each gate again on each stored result and makes no model call.
