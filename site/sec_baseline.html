10. A review with no proof duty

The runs above show that a proof adversary finds gaps. They do not show that the proof is necessary to find them. A reader can ask the same model the same question with no proof duty. We ran that test after the first release of this draft. It also found a fault in our own blind set.

The tasks

The test has {{BL_RUNS}} decision points from the study: the lock with three laws and with four laws, the sync command with seven laws and with eight laws, each adversary round of the nine loops with agent-written laws, and the blind tables of Section 8 in four sizes. At each point the truth is known, because the gate accepted a gap certificate or a completeness proof there. {{BL_GAP_TASKS}} points have a gap, and {{BL_COMPLETE_TASKS}} are complete.

A reviewer agent got the same model file, laws and description as the proof adversary. It got no gate script and no solution file. The folder name was a hash, and comments that told the history of a law were removed. The brief says that one of two results is true, that no proof is necessary, and that no checker reads the answer. The reviewer writes one file: the verdict, and for a gap one concrete input with the two results. The reviewer had no shell: it could read and write files only. The models were Haiku 5.5 and Sonnet 5.5.

The score has two parts. The verdict is compared with the truth. A gap answer must also name a real gap. For the tables a script checks that the named case has no law. For the other domains the pilot read each gap answer and compared it with the certified question of that decision point.

The cost and time of the proof worker are for the accepted run at the same decision point with the same model. They do not include the time of the gate.

What the review found

The verdict was correct in {{BL_VERDICT_OK}} of {{BL_RUNS}} reviews. A gap was found and was a real gap in {{BL_GAP_VALID}} of {{BL_GAP_TASKS}} gap tasks. A complete law set got a false gap in {{BL_FALSE_GAP}} of {{BL_COMPLETE_TASKS}} tasks. The reviews cost {{BL_COST}} and took {{BL_SECONDS}} s of worker time. The proof workers at the same points cost {{BL_PROOF_COST}} and took {{BL_PROOF_SECONDS}} s.

For each gap in the lock, in the sync command with seven laws, and in the recovery rule, the review named the same decision as the certified question: a release that does nothing, the order of the new rows, an age that is unknown, an age equal to the limit. The review did this for less money and in less time. For these gaps the proof was not necessary to find the gap.

What the review missed

Six reviews were wrong. Three were table tasks with 128 and 512 laws: two gap answers named a case that a law covers, and one review of a complete set reported a gap. The other three were in the sync loops with agent-written laws. In each, the true result is a gap: a legal starter list can hold one entry two times, because the pilot's definition DistinctIds permits it (Section 7). Each of the three reviews said "complete", with a reason of this form: "With distinct starter ids, the laws fix the tail".

We ran the six tasks again in three more arms: the same review a second time, a review with a shell (Lean, Lake and Python), and a review by Opus 5.5.

{{TABLE_BASELINE_FOLLOW}}

Each arm corrected the three table errors. No arm found the duplicate entry. In {{BL_DUP_MISSED}} of {{BL_DUP_REVIEWS}} reviews, on three law sets, with two models, with and without tools, the answer was "complete". Each reason uses the name of the definition and not its text. The definition was in the model file that each reviewer read. The proof adversary found this gap at each of the three points, and the gate accepted each certificate.

What this test shows

  • A plain review finds the gaps that a careful reader sees. It found them at about the same cost as the proof worker, and in less time. A result of the form "the adversary found the gap" is weak evidence for a proof gate when a review finds the same gap.
  • The proof duty found the gap that the review missed. The gap depends on the exact text of a definition. A reviewer that reasons from the name of the definition gives a wrong "complete". A proof adversary cannot end there, because the gate accepts no completeness proof for these laws.
  • A wrong review looks the same as a correct review. The six wrong answers have the same form and the same sure tone as the {{BL_FULL_OK}} correct answers. A repeat, tools and a larger model corrected the table errors, but the reader cannot know which answers need a repeat. With the gate, a wrong answer is a rejected file.
  • The count is small. The missed gap is one fault, on three law sets that share one definition file. We did not measure how frequently a gap of this kind occurs. The first arm used two models. The other three arms ran on the six errors only, so they do not show the errors that those arms make on the other tasks. The pilot judged 16 gap answers by reading. The review brief has one version.

A fault in the first blind set

While we built this test, we found a fault in the blind set of Section 8. Each of its runs was in a folder with the word "gap" or "complete" in the path, and the flow id had the same word. A worker that read its own path knew which result was true. The path did not say which case is open. We searched the 24 stored transcripts: 448 tool calls, no read outside the run folder, and no visible sentence that names the folder. The reasoning text of the workers is not stored, so we cannot exclude that a worker used the path.
